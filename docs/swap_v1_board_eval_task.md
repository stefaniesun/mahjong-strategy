# 换三张四家盘面大样本模拟与盲区校准任务（v1 → v2）

## 一、任务目的

本任务用于在多核 CPU 机器上运行**“换牌完成 + 四家定缺落地”阶段的大规模四家盘面模拟**，不跑后续摸打牌局（彻底隔离后续出牌 AI 的水平偏差与摸牌运气噪音）。

所有模拟中，牌桌另外三家均使用符合正常实战常识的 **`swap_v1` + `void_v1` 策略**作为陪练，重点产出三份核心数据供下一轮校准通用评分尺子（升级 `v2`）：

1. **真实进牌画像**：正常玩家实际换出的三张牌型比例（孤张、嵌边搭、两面搭、对子、顺子/刻子）及不同持牌数下的撞花色分布；
2. **14 个庄闲核心纠结结构桶的大样本对账**：在完全相同的初始手牌与外部洗牌下，对比 `legacy`、`principled`（现行 S3）与 `v1` 的向听步数、缺门卡壳率、清一色底子率、喂肥对手率与单行道风险；
3. **自动盲区错题本（`top_v1_disagreements`）**：在每手随机牌上遍历全部合法换法，抓出“`v1` 选择明显落后于四家盘面最优解”的具体牌例，用于精准修正通用评分刻度。

## 三、换机拉取与环境自检（约 5 秒）

在算力机器上拉取最新代码后，先跑一次单测与极小冒烟，确认依赖与多核进程池工作正常：

```powershell
git pull
python -m pytest tests/test_swap_v1.py -q
python tools/run_swap_v1_eval.py --hands-per-bucket 5 --deals-per-hand 5 --workers 4 --out outputs/swap_v1_check.json
```

看到 `4 passed` 且几秒内输出 8 行分桶进度即说明环境一切正常。

## 四、正式大样本运行命令

脚本默认覆盖 **8 个闲家纠结桶**（`4/4/5`、`3/4/6`、`3/5/5`、`3/3/7`、`2/5/6`、`2/4/7`、`1/5/7`、`1/6/6`），加上 `--include-dealer` 后同时覆盖 **6 个庄家纠结桶**（`4/5/5`、`4/4/6`、`3/5/6`、`3/4/7`、`2/5/7`、`2/6/6`），共 **14 个分桶**。

> **关于 `--workers` 参数**：若不手动传 `--workers`，脚本会自动使用 `逻辑CPU核数 - 1`。也可手动指定（例如 16 核 32 线程机器推荐设为 `24`～`28`，避免把系统彻底占满）。

### 推荐档位 A：标准主力大样本（28,000 手随机牌 / 280 万次四家发牌）

适合 12～32 线程 CPU，预计耗时约 **25～50 分钟**，统计误差已压到极低，足够支撑 `v2` 定稿：

```powershell
python tools/run_swap_v1_eval.py --hands-per-bucket 2000 --deals-per-hand 100 --include-dealer --resume --out outputs/swap_v1_eval_large.json
```

*(若要手动指定进程数，在后面追加 `--workers 24` 即可。)*

### 推荐档位 B：重度精校超大样本（70,000 手随机牌 / 840 万次四家发牌）

如果机器核数很多（如 32～64 线程）或准备挂机 1.5～2 小时，可直接跑这一档，连极稀有牌型的边界都能彻底摸透：

```powershell
python tools/run_swap_v1_eval.py --hands-per-bucket 5000 --deals-per-hand 120 --include-dealer --resume --out outputs/swap_v1_eval_xl.json
```

## 五、断点续跑与进度观察

1. **实时进度**：每跑完 1 个分桶（共 14 个），终端会立刻打印一行汇总，例如：
   ```text
   [non_dealer|2/4/7  ] 2000手x100局 (42.1s) | v1胜现行S3: +0.812 (±0.028) | 近似最优率: 78.5% (精确第一:42.1%) | 向听 2.80->2.52 卡壳 21.0%->0.0% 喂敌 52.8%->57.1%
   ```
   - `v1胜现行S3`：正数且大于括号内 `±置信半宽`，表示 `v1` 在该桶显著优于现行策略；负值则代表该桶存在待校准刻度。
   - `近似最优率`：`v1` 的单手盲算结果距离“开天眼测遍所有候选后的四家盘面第一名”差距在 `0.05` 以内的比例。

2. **自动断点保护（`--resume`）**：
   - 每完成一个分桶，程序都会自动更新同目录下的 `outputs/swap_v1_eval_large.json.ckpt.json`；
   - 若中途关闭窗口或重启机器，**重新执行完全相同的命令**（保留 `--resume` 和相同的 `--out` 路径），程序会自动跳过已完成的桶继续往下跑。

## 六、跑完后如何带回结果

任务全部跑完后，只会生成一个几 MB 大小的汇总 JSON 文件（例如 `outputs/swap_v1_eval_large.json`）。

你有两种方式带回这台电脑继续下一步迭代：

1. **直接复制文件**：把生成的 `outputs/swap_v1_eval_large.json` 拷回本项目的 `outputs/` 目录下即可；
2. **或者通过 Git 提交带回**（因为 `outputs/` 默认在 `.gitignore` 中忽略，需加 `-f` 强制添加该结果文件）：
   ```powershell
   git add -f outputs/swap_v1_eval_large.json
   git commit -m "data: add large-scale swap v1 board evaluation report"
   git push
   ```

拿到这份大样本文件后，我们即可统一校准通用评分刻度（修正庄家首打 1 张缺门红利、缺门张数阶梯扣分、粘连对子重复计分等），完成 `swap_v2` 并接入 `assistant` 辅助器面板。
